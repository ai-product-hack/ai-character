# Разведка стека: голосовой тренажёр с говорящим аватаром

Фаза 0. Дата: 2026-09-03. Железо замеров: MacBook Air M4 (10 CPU / 8 GPU),
16 ГБ unified, macOS 26.6.2. Всё, что названо измеренным, померено здесь;
сырьё лежит в `bench/results/`.

## Запуск demo app

Нужны Python 3.11+ и Node.js 20+. Первый запуск требует интернета: Silero
загружается через `torch.hub`, а модель выравнивания GigaAM — с Hugging Face.

```bash
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements-demo.txt
npm ci --prefix avatar
cp .env.example .env
```

В `.env` обязательно заполнить `DEEPSEEK_API_KEY` — он ведёт диалог.
`ANTHROPIC_API_KEY` нужен генератору сценариев из текста: без него сервер
поднимается как обычно, селектор готовых сценариев работает, а генерация
отвечает шаблоном с честным сообщением. `ELEVENLABS_API_KEY` нужен только для
сетевого голоса; без него demo полностью работает на офлайновом
`Silero (ru_roman)`. Ключи не коммитятся: `.env` уже находится в `.gitignore`.

**Выполните до демонстрации** — скачивание моделей отдельным шагом, чтобы
первый запуск сервера не уходил в сеть на глазах у зала:

```bash
.venv/bin/python app/preload.py
```

Тянет Silero (89 МБ, ~1.5 минуты) и GigaAM (429 МБ) в кеш пользователя,
проверяет оба пробным синтезом и выравниванием и возвращает ненулевой код,
если что-то не поднялось. Повторный запуск занимает секунды и ничего не качает.

Запуск сервера:

```bash
.venv/bin/python app/server.py
```

После строки `готово` открыть два экрана:

- методист: <http://localhost:8010/app/web/methodist.html> — собрать сценарий
  и утвердить его;
- сотрудник: <http://localhost:8010/app/web/trainee.html> — вести диалог.

## Сценарий из текста

Экран методиста начинается с одного большого поля. Туда вставляется что
угодно: техзадание, описание вакансии с вилкой, скрипт продаж, регламент,
требования свободным текстом. Выбор типа тренировки рядом — подсказка
генератору, а не обязательное поле.

Один вызов модели даёт три вещи:

- **персону собеседника** — роль, тон, строгость, манеру давления и стартовую
  эмоцию (одну из семи, включая `angry` и `anxious`). Это и есть «персонаж из текста»: из вакансии на Rust-разработчика и
  из скрипта холодных продаж получаются заметно разные собеседники. Персона
  уходит в системный промпт сессии и в начальное состояние лица;
- **этапы** — 5–7, у каждого цель, подсказка модели, условие перехода и
  собственный бюджет ходов;
- **критерии оценки** — вытащенные из текста. Требования вакансии и есть
  критерии; ключ латиницей генерируется из названия, придумывать
  идентификаторы не нужно.

Дальше артефакт **полностью редактируется**: этапы переставляются, удаляются и
дописываются, критерии правятся, персона меняется текстом. **Approve**
замораживает версию — сессия работает с неизменяемой копией, и правки после
approve на идущий диалог не влияют. Тогда же выдаётся ссылка вида
`trainee.html?session=…`, которую открывает сотрудник.

Ниже — чат-слой: «сделай третий этап жёстче», «добавь критерий про
английский». Артефакт перегенерируется частично, и поля, которые методист
правил руками, возвращаются на место после ответа модели — полагаться в этом
на послушность модели нельзя.

Селектор готовых сценариев остался на соседней вкладке: страховка на показе и
способ увидеть валидный сценарий мгновенно, не дожидаясь генерации.

Надёжность генерации — три слоя: строгая схема на выходе, повтор с текстом
ошибки в промпте (до двух раз), фолбэк на шаблон по типу тренировки с честным
сообщением методисту. Индикатор прогресса показывает номер попытки: генерация
идёт **до** диалога и занимает 35 секунд по медиане, тишины в это время быть не
должно. Нужен `ANTHROPIC_API_KEY`; без него сервер поднимается как обычно, а
генерация отвечает шаблоном — селектор готовых работает всегда.

Прогон тринадцати входов, по одному на механику диалога, и честный разбор
качества — в [scenarios/REPORT.md](scenarios/REPORT.md).

## Отчёт

Появляется **на экране в момент `finish`** — у сотрудника поверх сцены, у
методиста в его вкладке. Скачивать ничего не нужно.

В отчёте: шапка со сценарием, персоной, датой и длительностью; общий вывод
текстом; оценка по каждому критерию **с цитатами**; транскрипт разговора чатом,
с ролями и временем.

Цитата — главное здесь. Фоновая сессия, выставляя оценку, записывает **индекс
реплики**, которая её обосновала, а не копию текста. Клик по цитате
прокручивает транскрипт к нужному месту и подсвечивает реплику. Разница
принципиальная: «коммуникация 3 из 5» — мнение модели, «3 из 5, вот ответ, где
кандидат поплыл» — инструмент.

PDF делает сам браузер: Cmd+P, отдельная таблица стилей `@media print`, никаких
новых зависимостей. JSON дописывается одной строкой в
`data/reports/history.jsonl` — история прогонов без базы данных.

На экране сотрудника есть тумблер микрофона: голосовой ввод идёт вторым путём,
текстовый остаётся основным. **Нужны наушники** — иначе микрофон услышит
аватара. Рядом кнопка «говорить» (push-to-talk) на случай, если определение
конца хода режет невпопад.

Там же голос переключается без перезапуска между
`Silero (ru_roman)` и `ElevenLabs`. Первая загрузка ElevenLabs может занять
несколько секунд: проверяется ключ и заранее переозвучиваются заполнители.
Если ключа нет или API недоступен, выбор останется на Silero, а рядом с
селектором появится причина. Во время диалога первый сбой ElevenLabs включает
Silero до перезапуска, чтобы голос не менялся туда-обратно между фразами.

Для другого порта: `.venv/bin/python app/server.py --port 8011`. Экран
сотрудника открывается воротами «начать разговор»: браузер включает звук только
по жесту, и без этого первая реплика уходила в тишину. Кадры до нажатия
копятся на сервере, так что ничего не теряется. Настройки провайдеров, модели и
voice ID находятся в [`app/config.json`](app/config.json).

## Что нужно от команды

1. **Живые записи** — `python3 bench/data-gen/record_live.py --device 1`,
   ~15 минут. Разблокирует выводы R1 (термины) и R2 (конец хода). Самое важное.
2. **Решение по LLM.** Ключ появился, замер сделан: DeepSeek даёт TTFT
   1899 мс, и метрика 3000 мс выполняется в **13 случаях из 20** даже со
   спекуляцией. Нужно решить — принимаем и маскируем бэкчэннелом, или ищем
   более быстрого провайдера. См. `RISKS.md`, риск №4.
3. **Прогон R6** — `cd bench/r6-echo && ./run.sh`, ~10 минут, нужен человек.
4. **Аватар из Avaturn** в `data/avatars/` — проверка занимает минуту.
5. **Послушать** `bench/r3-tts/samples/` и выбрать голос: оценку на слух
   я сделать не могу.

## Репетиция

    bench/r1-stt/.venv/bin/python app/run_rehearsal.py

Гоняет все пять сценариев через **настоящий сервер по HTTP** — тем же путём,
что браузер, — со случайными перебиваниями и с набором текста порциями, как у
человека. Кладёт всё в `bench/results/rehearsal.json` и печатает сводку: первый
звук, спекуляция, эмоции, перебивания, доля реплик без управляющей строки,
динамика набора.

Отличие от `app/run_pipeline.py` принципиальное: тот дёргает конвейер напрямую
и потому не видит ничего, что живёт в сессии — заполнитель, спекуляцию, теги
эмоций, сигнал набора, второй разбор действия.

Гоняет оба режима ввода: часть ходов идёт текстом с набором по частям, часть —
голосом (реплика пользователя синтезируется и подаётся на `/api/audio` теми же
кусками PCM, что шлёт браузер, через тот же VAD и тот же распознаватель).

Полезные ключи:

    --scenario s3_sales_cold     один сценарий вместо пяти
    --turns 30                   потолок ходов (сценарий обычно кончается раньше)
    --min-interrupts 2           гарантировать N перебиваний в каждом сценарии
    --voice-every 3              каждый n-й ход голосом; 0 — только текст
    --interrupt-rate 1.0         вдобавок перебивать случайные реплики
    --seed 42                    перебивания воспроизводимы

Возвращает ненулевой код, если после отмены просочился хоть один кадр
погашенной генерации или если до `finish` дошли не все сценарии.

Не меряется здесь ровно одно: как это выглядит. FPS и дрейф требуют рендера, и
их показывает оверлей в самом приложении (`app/web/trainee.html`, включён по
умолчанию, прячется кликом).
