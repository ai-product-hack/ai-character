Стенд: MacBook Air M4, Chrome 152, DeepSeek `deepseek-chat`, Silero v4_ru

## Дрейф аудио и мимики — первое честное измерение

Приёмочные 0.0 мс модуля аватара были получены на синтетическом треке, который
сам же и порождён: проверка арифметики, а не синхронизации. Теперь звук
настоящий, таймкоды получены выравниванием этого звука, а трек висем построен
слоем g2p.

| | значение |
|---|---|
| дрейф p50 / p95 / макс | **0.0 / 0.0 / 0.0 мс** (порог 50) |
| кадров рендера | 1077, из них 518 во время артикуляции |
| подвисаний | 0 |
| кадров с чужим `generation_id` | 0 |

Дрейф на оверлее — это расстояние до имеющихся кадров, и ноль там получается
по построению, пока рендер не выходит за пределы трека. Поэтому отдельно
измерена **настоящая синхронность**: огибающая из тракта голоса против
активности рта, сдвиг подбирается перебором.

| | значение |
|---|---|
| совпадение при нулевом сдвиге | **84.4%** |
| лучший сдвиг | **0 мс** |
| совпадение на лучшем сдвиге | 84.4% |

Смещение не улучшает совпадение ни на йоту — **систематического рассинхрона
нет**. Для сравнения, тот же метод на заготовленных сэмплах в модуле аватара
давал 67–81% при медианном сдвиге 0.

# Замеры третьей фазы

Стенд тот же. Изменилось: голос **Silero v5_cis_base `ru_roman`** вместо v4_ru
`eugene`, добавлены заполнитель, спекуляция, теги эмоций, сигнал набора и
второй разбор действия.

Сырьё: `bench/results/rehearsal.json`, `bench/results/r4_align_synth_ru_roman.jsonl`,
`bench/results/r3_tts_round2_elevenlabs.jsonl`.

## Первый звук: 2572 → 126 мс

Главная цифра фазы. Мерена **по-настоящему**: репетиция ходит по HTTP тем же
путём, что браузер, и засекает приход первого звукового кадра, а не момент,
когда сервер о нём узнал.

| | было (фаза 2) | стало |
|---|---|---|
| первый звук, медиана | 2572 мс | **127 мс** |
| первый звук, максимум | 3364 мс | **141 мс** |
| первая содержательная речь, медиана | 2572 мс | 2112 мс |

80 реплик пяти сценариев, 20 из них перебиты. Заполнитель не «обычно
успевает», он успевает всегда. Цена: содержательная реплика начинается на те же
2.1 с, что и раньше. Мы не ускорили модель, мы убрали тишину.

Заполнитель встал в **100%** реплик. Это не сбой порога: `after_ms` = 120 мс, а
TTFT DeepSeek около 2 с, так что случай «модель ответила раньше» на этом
провайдере просто не наступает. Ветка «без заполнителя» существует для
спекулятивных попаданий и для более быстрого провайдера.

## Управляющая строка: дыра измерена и закрыта

В задании стояло «около 10% ходов приходят без последней строки». Теперь это
цифра, а не оценка.

| | значение |
|---|---|
| реплик без управляющей строки | **1.7–4.1%** по трём прогонам |
| из них восстановлено вторым разбором | **все** (6 из 6 суммарно) |
| стоимость второго разбора, медиана | **2127 мс** |

Второй разбор — отдельный дешёвый запрос (`max_tokens=8`, `temperature=0`) по
уже сказанному тексту. На первый звук он не влияет: реплика к этому моменту
звучит. Влияет на момент обновления этапа — примерно две секунды, и только на
тех 8% ходов, где строки не было.

## Динамика набора

| | значение |
|---|---|
| ответов с сигналом | 75 |
| «уверенно» / «с заминками» / «неуверенно» | 73 / 2 / 0 |

Сигнал идёт в отчёт по каждому ответу и сводкой по диалогу. В поведении он
гасит нарастающее нетерпение: часы нетерпения отделены от часов состояния и
сбрасываются на каждое нажатие клавиши, локально в браузере — ждать сети, чтобы
не торопить человека, значит торопить его лишние 250 мс.

## Эмоции

Теги `[emo:...]` приходят в тексте реплики, вырезаются до синтеза и едут по
тому же PTS, что висемы и субтитры.

| | значение |
|---|---|
| проставлено за репетицию | 4 на 80 реплик |

Модель ставит их скупо и по делу: `skeptical` на слабом ответе в сценарии
возражений, `neutral` на нейтральном. На заготовленных «правильных» репликах
эмоциональных поводов почти нет — это свойство сценария прогона, а не поломка.

## Переключатель синтезаторов

| | Silero v5 `ru_roman` | ElevenLabs `eleven_flash_v2_5` |
|---|---|---|
| синтез клаузы, медиана | **77 мс** | 322 мс |
| синтез клаузы, p90 / макс | 93 / 119 мс | 484 / 544 мс |
| выравнивание, медиана | 76 мс | 106 мс |
| ступень целиком, медиана | **150 мс** | 436 мс |
| работает без сети | да | нет |

Замерено на 15 клаузах пяти реплик. Обе величины много меньше длительности
клаузы (2–5 с), так что конвейеризация держится в обоих случаях: следующая
клауза готова задолго до конца текущей.

ElevenLabs берётся по HTTP-потоку, не по websocket. WS даёт TTFB 278 мс
(медиана, n=20 на преоткрытых соединениях), но нам нужна **клауза целиком**:
её всё равно надо выровнять локально, чтобы получить таймкоды висем. Первые
байты раньше конца клаузы ничего не дают.

Silero остаётся офлайновым запасным при любом выборе: при первом же сбое
сетевого синтеза голос переключается на локальный и остаётся на нём до
перезапуска. Метаться туда-обратно нельзя — это меняло бы голос посреди фразы.

## Латиница и цифры пропадали из речи

Найдено при проверке терминов, не по чужой наводке. Русская модель Silero не
заменяет незнакомые символы и не читает их по буквам — **стирает молча**:

| текст реплики | что слышно было |
|---|---|
| «Расскажите про ваш backend и REST API.» | «расскажите про ваш и» |
| «SLA у нас 99.9 процента.» | «у нас процента» |
| «Задержка сто миллисекунд на p95.» | «задержка ста миллисекундно» |

Для тренажёра собеседований это не мелочь: реплики агента состоят из терминов и
цифр. Хуже того, субтитры показывали исходный текст — то есть человек видел
осмысленную фразу и слышал обрубок.

Починено нормализацией перед синтезом (`app/pronounce.py`): числа разворачиваются
в слова, латиница — в кириллицу по словарю, аббревиатуры читаются по буквам,
незнакомое транслитерируется. **В субтитры идёт исходный текст** — «p95»
читается глазами лучше, чем «пи девяносто пять».

| | до | после |
|---|---|---|
| сходство расшифровки с произнесённым, медиана | — (термины отсутствовали) | **0.96** |
| то же, минимум по 8 репликам | — | 0.92 |
| интервал символов | 40 мс | **40 мс** |
| клауз без таймкодов | — | **0** |

### Аббревиатуры пишутся слитно, и это измерено

Первая версия словаря разделяла буквы дефисами (`эй-пи-ай`). Замер показал, что
слитная форма выравнивается лучше **во всех пяти проверенных случаях**:

| аббревиатура | дефисами | слитно |
|---|---|---|
| SQL | 0.96 | **1.00** |
| HR | 0.90 (**ноль таймкодов**) | **0.97** |
| KPI | 0.86 | **0.95** |
| SLA | 0.80 | **0.93** |
| API | 0.88 | **0.91** |

`эйч-ар` выровнялся в пустоту: таймкодов ноль, а значит на этом слове рот не
двигается вовсе. Это тот же класс отказа, что уже ловили на пороге быстрой
речи, — беззвучный, видимый только на замере.

# Трек А: замеры после доработки

Стенд тот же. Все числа — из `bench/results/rehearsal.json`: пять сценариев
через настоящий сервер по HTTP, два перебивания в каждом, каждый третий ход
голосом.

## Завершение сценариев: 3 из 5 -> 5 из 5

Единственная метрика кейса, которую мы проваливали.

| | было | стало |
|---|---|---|
| дошли до `finish`, без перебиваний | 3 из 5 | **5 из 5** |
| дошли до `finish`, по 2 перебивания в каждом | 1 из 5 | **5 из 5** |
| дошли до последнего этапа | 5 из 5 | 5 из 5 |
| кадров погашенной генерации после отмены | 0 | **0** |

Что чинилось. Перебитая реплика списывала бюджет этапа: пользователь услышал
часть реплики и ответил на неё, а движок считал ход потраченным. Теперь такой
ход в бюджет не идёт. Прозвучавшая часть терялась из истории целиком — при
отмене `speak` выходил раньше, чем доходил до применения действия, и агент
переспрашивал то, на что уже получил ответ.

Диагноз из задания «исчерпание бюджета на последнем этапе ни к чему не
приводит» **не подтвердился**: ветка есть и закреплена тестом. Настоящая
причина была в лимите ходов прогона — сценарий не успевал израсходовать бюджет
последнего этапа. Последнему этапу дан лимит на ход больше.

Так как перебитые ходы перестали списывать бюджет, добавлен потолок на весь
диалог: иначе собеседник, перебивающий каждую реплику, не дал бы сценарию
закончиться никогда.

## Спекуляция: разбор показал, что мерили не то

«55 попаданий из 55» и содержательная реплика на 2.1 с несовместимы. Причина
нашлась сразу, как появились отметки времени.

| | до | после |
|---|---|---|
| фора до нажатия Enter, медиана | 344 мс | **635 мс** |
| токенов накоплено к Enter | **0** | 0 |
| TTFT при попадании | 1926 мс | **1604 мс** |
| первая содержательная речь | 2275 мс | **1966 мс** |

Попадание считалось по совпадению префикса, а не по сэкономленному времени.
Перезапуск по росту буфера гасил предыдущий полёт, а последний перезапуск
приходился на конец набора: мы платили токенами и не получали ничего. Теперь в
воздухе до трёх запросов, ранний живёт до отправки.

**Ноль накопленных токенов — это потолок, а не недоделка.** Фора ограничена
временем набора, умноженным на (1 − порог покрытия): при наборе в 1.6 с и
пороге 0.6 это ~640 мс, и мы на нём. Остаток задержки — TTFT провайдера.

## Голосовой ввод

| | значение |
|---|---|
| первый звук от решения эндпоинтера | **122 мс** |
| то же на текстовом пути | 127 мс |
| распознавание реплики | 152 мс медианы |

Метрика на голосе не поехала. Порог тишины 1000 мс взят из R-фазы и проверен
на живых записях (`bench/r2-endpoint/verify_voice.py`): **0 ложных срезов из 20
заминок, 5 из 5 терминальных фраз пойманы**.

Метод замера пришлось поправить: записи подрезаны по концу речи, хвостовой
тишины в них 0–180 мс, и сначала ни одна терминальная фраза не ловилась —
порогу нечего было ждать. Терминальным хвост достраивается, заминкам нет:
дописанная в конец тишина означает, что человек договорил.
