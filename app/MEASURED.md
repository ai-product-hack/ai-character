# Замеры вертикального среза

Всё, что раньше мерилось на синтетике, перемерено на настоящих данных.
Стенд: MacBook Air M4, Chrome 152, DeepSeek `deepseek-chat`, Silero v4_ru
голос `eugene`, GigaAM v3 CTC.

Сырьё: `bench/results/live_path.json`, `bench/results/pipeline_final.json`,
`bench/results/cancel_pipeline.json`, `bench/results/r4_align_synth_eugene.jsonl`.

## Дрейф аудио и мимики — первое честное измерение

Приёмочные 0.0 мс модуля аватара были получены на синтетическом треке, который
сам же и порождён: проверка арифметики, а не синхронизации. Теперь звук
настоящий, таймкоды получены выравниванием этого звука, а трек висем построен
слоем g2p.

| | значение |
|---|---|
| дрейф p50 / p95 / макс | **0.0 / 0.0 / 0.0 мс** (порог 50) |
| кадров рендера | 1077, из них 518 во время артикуляции |
| подвисаний | 0 |
| кадров с чужим `generation_id` | 0 |

Дрейф на оверлее — это расстояние до имеющихся кадров, и ноль там получается
по построению, пока рендер не выходит за пределы трека. Поэтому отдельно
измерена **настоящая синхронность**: огибающая из тракта голоса против
активности рта, сдвиг подбирается перебором.

| | значение |
|---|---|
| совпадение при нулевом сдвиге | **84.4%** |
| лучший сдвиг | **0 мс** |
| совпадение на лучшем сдвиге | 84.4% |

Смещение не улучшает совпадение ни на йоту — **систематического рассинхрона
нет**. Для сравнения, тот же метод на заготовленных сэмплах в модуле аватара
давал 67–81% при медианном сдвиге 0.

## FPS с работающим конвейером

Раньше 60 FPS мерились на статичной модели. Теперь одновременно работают сеть,
декодирование аудио, обновление субтитров и все пять слоёв лица.

| | значение |
|---|---|
| FPS p50 | **60.0** |
| FPS p05 | 56.2 |
| FPS минимум | **56.0** |

Провалов ниже 56 нет. Конвейер стоит около 4 FPS в худшем перцентиле.

## Время до первого звука

| | значение |
|---|---|
| от Enter до первого звука, браузер | **2717 мс** |
| по 66 репликам пяти сценариев, медиана | **2572 мс** |
| p90 / максимум | 2993 / 3364 мс |
| из них TTFT модели, медиана | 2252 мс |

По сценариям (медианы): s1 — 2591, s2 — 2631, s3 — 2568, s4 — 2502, s5 — 2599 мс.
Разброс между сценариями меньше 130 мс: длина промпта и персона на первый звук
почти не влияют, всё определяет провайдер.

Разложение измерено отдельно: TTFT DeepSeek около 1790 мс на коротком промпте,
плюс 348 мс за размер нашего промпта, остальное — синтез первой клаузы,
выравнивание и накладные.

**Это не регрессия среза.** S1 мерил TTFT DeepSeek 2058 мс ещё в R-фазе.
Стратегия S1 к текстовому вводу не переносится: спекулятивная генерация прятала
TTFT под речью пользователя, а речи после ревизии от 03.09 больше нет.

## Задержка остановки при перебивании

Порог кейса — 300 мс. Мерилось от нажатия Enter до тишины и до закрытого рта.

| точка перебивания | звук | рот | протечек |
|---|---|---|---|
| до первого звука | **14 мс** | 17 мс | 0 |
| в середине речи | **15 мс** | 133 мс | 0 |
| в конце реплики | **32 мс** | 117 мс | 0 |

Рот закрывается за 117–133 мс: это ускоренное схлопывание из состояния
`interrupted` (постоянная времени 45 мс), а не задержка тракта.

Отдельно, на серверной стороне (`cancel_pipeline.json`): остановка 0 мс во всех
трёх точках, **ни одного кадра с чужим `generation_id`**.

движке с заглушкой: реальная модель, реальный синтез, реальное выравнивание.

## Выравнивание синтеза против живой речи

Гейт из задания: перенос качества выравнивания нельзя считать автоматическим.

| | WER медиана |
|---|---|
| живая речь (R1, 35 записей) | 0.125 |
| синтез Silero `eugene` (10 реплик) | **0.037** |

Выравнивание синтеза работает **лучше**, а не хуже: ровный темп и отсутствие
пауз дыхания распознавателю помогают. План по липсинку менять не потребовалось.

## Интервал между символами

Поправка 80 мс была выведена из живой речи и к синтезу не подошла.

| | значение |
|---|---|
| медиана интервала внутри слов, `eugene` | **40 мс** |
| смен висем ровно на сетке 40 мс | 54.6% |
| срабатываний ограничителя при пороге 80 | **73% речи** |
| срабатываний при пороге 40 | 16.3% |

Порог опущен до 40. Инвариант «не выше шага таймкодов» закреплён тестом:
выше сетки ограничитель превращается в постоянно включённый, и рот не
открывается — тот же провал, что уже ловили на длительности символа, только
пришедший через выбор голоса.
